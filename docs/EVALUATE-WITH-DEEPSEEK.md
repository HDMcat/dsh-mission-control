# 用你自己的 DeepSeek 评估 DSH Mission Control

把下面整段提示词交给你的 DeepSeek（需要能访问 GitHub/网页）。它先分析和判断，**不要自动安装**。

---

```text
你是我的 DSH（DeepSeek Harness）环境评估助手。请实际访问并阅读：

仓库：https://github.com/HDMcat/dsh-mission-control
要求：至少读取 README、docs/ARCHITECTURE.md、docs/DSH-PLUGIN.md、docs/VERIFICATION.md、package.json；必要时读取用户指定的源码文件。不要只根据仓库简介回答。

我的环境（请按实际情况替换）：
- DSH 版本：[填写]
- 操作系统：[Windows / macOS / Linux + 版本]
- 我主要用它：[写代码 / 跑 Agent / 本地模型 / 其他]
- 是否允许插件起本地子进程：[是/否]
- 是否允许监听 127.0.0.1 的 7799/7800：[是/否]
- 是否有隐私/合规限制：[填写]

请完成：
1. 找到仓库当前 main 的 commit、版本、许可证；
2. 说明插件到底做什么、哪些数据在本地、哪些会写文件或开端口；
3. 分析功能、性能开销和隐私边界；区分“真实测量”和“N/A/不可读”；
4. 结合我的环境，判断我是否适合安装，给出明确结论：
   - 建议安装 / 不建议安装 / 先做验证再决定
5. 若建议安装，给出官方 DSH 插件管理器步骤，以及本地路径安装方式；不要执行未知脚本；
6. 给出验证清单、回滚/卸载步骤、失败时的排查点；
7. 标注你实际读过的文件和 URL；没查到的内容写“未验证”，不要编造。

输出格式：
- 一句话结论
- 价值（3 点）
- 风险与边界（3 点）
- 与我的环境匹配度
- 安装步骤（编号）
- 验证 / 回滚
- 引用来源

最后再问我一次：“是否要按这些步骤安装？”在我明确确认前不要安装或修改我的 DSH。
```

## 一段更短的分享版

```text
请访问 https://github.com/HDMcat/dsh-mission-control ，读取 README 和 docs，分析这个 DSH 插件的功能、隐私边界和安装成本；再结合我的 DSH 环境，明确告诉我“建议安装 / 不建议安装 / 先验证”，并给出安装、验证和回滚步骤。不要自动安装，先给我判断。
```

## 适用边界

- 这是给用户自己的 DeepSeek/DSH 做**评估与决策**的提示词，不是自动安装器。
- 插件默认只监听本机回环；进程控制默认关闭。
- 视频/截图若未脱敏，先确认隐私后再公开。
